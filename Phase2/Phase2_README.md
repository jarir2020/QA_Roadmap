## Theory focus

Manual test design translates requirements into observable experiments. For each case, state the starting condition, action, expected result, and evidence that distinguishes success from failure. Partition inputs and workflows so the suite covers meaningful behavior without repeating equivalent examples. Record what was not tested; a passing checklist describes the executed scope, not the absence of defects.

This phase's AuthDemo cases build on Phase 1's risk and state model. The CRUD documents add entity lifecycle transitions, persistence assertions, and data-isolation reasoning. Phase 2's documentation update adds these explanations to the cases and execution checklist.
